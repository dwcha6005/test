==========================================================================
 [실습 시험] 회원가입 폼 자바스크립트 구현
==========================================================================

■ 제공 파일
  - join.html : 회원가입 화면 (수정 금지)
  - data.js   : 가입된 회원 목록 (JSON 배열, 수정 금지)
                [ { "id": "admin", "name": "관리자", "email": "admin@naver.com" }, ... ]
                ※ <script> 로 불러오지 말고 fetch() 로 요청하여 JSON 으로 읽을 것
                ※ 원래는 백엔드 서버에 이메일을 보내서 중복 여부만 받아야 하지만,
                   서버가 없으므로 data.js 를 서버 응답 대신 사용함

■ 실행 환경
  - fetch() 는 HTML 파일을 더블클릭(file://)으로 열면 동작하지 않음
    → 톰캣(JSP 프로젝트), VS Code Live Server 등 웹 서버에서 실행할 것

■ 제출 파일
  - join.js   : join.html 과 같은 폴더에 작성
                (join.html 하단에서 <script src="join.js" defer> 로 불러옴)

--------------------------------------------------------------------------
 [공통 작성 규칙]  ※ 지키지 않으면 감점
--------------------------------------------------------------------------
  1) HTML 파일을 수정하지 말 것. (onclick, onsubmit 등 이벤트 속성 추가 금지)
  2) 모든 이벤트는 JS 에서 addEventListener() 로 연결할 것.
     (element.onclick = function() { } 방식 사용 금지)
  3) jQuery 및 $() 같은 jQuery 스타일 함수 사용 금지
     → 요소는 document.querySelector() / querySelectorAll() 로 가져올 것.
  4) var 사용 금지 → const / let 사용.
  5) 이벤트 핸들러는 화살표 함수로 작성할 것. 예) btn.addEventListener("click", () => { ... });
  6) 글자 색상을 element.style.color 로 직접 지정하지 말고,
     메세지 영역(class="msg")에 아래 CSS 클래스를 추가하는 방식으로 표시할 것.
       - success : 초록색
       - warning : 주황색
       - error   : 빨간색
     예) <div class="msg success">사용 가능한 아이디!</div>
  7) 입력값을 검사하는 로직은 "값을 받아서 결과를 반환하는 함수"로 분리할 것.
     (검사 함수 안에서 document.querySelector 등 DOM 을 사용하지 말 것)
     예) validateId(id) → { valid: true, type: "success", message: "..." }
  8) 검증 결과를 전역 true/false 변수에 저장하지 말고,
     가입 버튼 클릭 시 현재 입력값으로 다시 검사할 것.
     (단, 이메일 중복확인은 서버 데이터가 필요하므로
      "중복확인을 통과한 이메일" 하나만 변수(checkedEmail)에 저장하는 것을 허용)

--------------------------------------------------------------------------
 [기능 요구사항]
--------------------------------------------------------------------------

 1. 아이디 (id="userId", 메세지 id="checkIdResult")
    - 키를 눌렀다 뗄 때마다(keyup) 검사, 앞뒤 공백은 제거하고 검사
    - 비어 있음          : 메세지 지우기
    - 4 ~ 8글자가 아님   : "4 ~ 8글자 사이 입력 필수!"       (error)
    - 영문 소문자, 숫자 외의 문자 포함
                         : "영문 소문자, 숫자만 사용 가능!"  (error)
    - 통과               : "사용 가능한 아이디!"             (success)
    - 아이디가 바뀌면 비밀번호에 값이 있을 경우 비밀번호 강도도 다시 검사할 것
      (비밀번호에 아이디가 들어 있는지가 달라지기 때문)

      예) abc → 길이 부족 / Hong1 → 대문자 사용 불가 / hong1 → 사용 가능

 2. 비밀번호 강도 (id="passwd", 메세지 id="checkPasswdResult")
    - 입력할 때마다(input) 검사
    - 검사 함수는 checkPasswordStrength(passwd, id) 처럼 아이디도 함께 받을 것
    - 허용 문자 : 영문 소문자, 영문 대문자, 숫자, 특수문자(!@#$%^&*)
    - 아래 순서대로 판정

      ① 길이가 8글자 미만 또는 16글자 초과
         → "불가 - 8 ~ 16글자 사이 입력 필수!"                         (error)
      ② 허용 문자 외의 문자(공백, 한글, 그 밖의 특수문자 등) 포함
         → "불가 - 영문, 숫자, 특수문자(!@#$%^&*)만 사용 가능!"        (error)
      ③ 비밀번호에 아이디가 포함됨 (대소문자 구분 없이, 아이디가 비어 있으면 검사 안 함)
         → "불가 - 비밀번호에 아이디를 포함할 수 없음!"                (error)
      ④ 4종류(소문자 / 대문자 / 숫자 / 특수문자) 중 사용한 종류의 개수 = 점수
      ⑤ 비밀번호가 12글자 이상이면 점수 +1 (단, 최대 4점)
      ⑥ 점수에 따라 등급 결정

         | 점수   | 등급 | CSS 클래스 | 가입 가능 |
         |--------|------|------------|-----------|
         | 4점    | 안전 | success    |    O      |
         | 3점    | 보통 | warning    |    O      |
         | 2점    | 위험 | error      |    O      |
         | 1점 이하| 불가 | error      |    X      |

         메세지 형식 : "등급 - N가지 조합"            (12글자 미만)
                       "등급 - N가지 조합 + 12글자 이상" (12글자 이상)
         1점 이하    : "불가 - 영문 대/소문자, 숫자, 특수문자 중 2가지 이상 조합 필수!"

      예) (아이디가 hong1 일 때)
          abcdefgh       → 불가 (1가지)
          abcd1234       → 위험 - 2가지 조합
          abcdefgh1234   → 보통 - 2가지 조합 + 12글자 이상
          Abcd123!       → 안전 - 4가지 조합
          Abcdefgh1234   → 안전 - 3가지 조합 + 12글자 이상
          xHONG1xx!A     → 불가 (아이디 포함)

 3. 비밀번호 확인 (id="passwd2", 메세지 id="checkPasswd2Result")
    - 입력할 때마다(input), 그리고 커서가 빠져나갈 때(blur) 검사
    - 비어 있음 : "비밀번호 확인 입력 필수!" (error)  ※ input 이벤트에서는 메세지만 지움
    - 일치      : "비밀번호 확인 완료!"      (success)
    - 불일치    : "비밀번호 다름!"           (error)
    - 비밀번호(passwd) 입력란을 수정해도, 비밀번호 확인란에 값이 있으면 다시 검사할 것

 4. 주민번호 (id="jumin1", id="jumin2", 메세지 id="checkJuminResult")
    - 두 입력란 모두 숫자 외의 문자를 입력하면 즉시 제거

    [앞자리]
    - 6자리가 되면 생년월일 검사 (3~4번째 자리 = 월, 5~6번째 자리 = 일)
      · 월이 01 ~ 12, 일이 01 ~ 31 이 아니면
        "생년월일 형식이 올바르지 않음!" (error) 표시, 커서 이동하지 않음
      · 올바르면 메세지 지우고 뒷자리 입력란으로 커서 이동
    - 6자리 미만이면 메세지 지우기

    [뒷자리]
    - 첫 숫자로 성별 라디오 버튼 자동 선택
      · 1, 3 → 남 / 2, 4 → 여
      · 그 외 : "주민번호 뒷자리 첫 숫자는 1 ~ 4만 가능!" (error)
    - 7자리 입력 완료 시 생년월일을 표시하고 커서 제거
      · 첫 숫자 1, 2 → 1900년대 / 3, 4 → 2000년대
      · 형식 : "1999년 03월 15일생 (남)" (success)

      예) 990315 - 1234567 → 1999년 03월 15일생 (남), 남 자동 선택
          050101 - 4xxxxxx → 2005년 01월 01일생 (여), 여 자동 선택
          991315           → 생년월일 형식 오류 (13월)

 5. 휴대폰번호 (id="phone", 메세지 id="checkPhoneResult")
    - 입력할 때마다(input) 숫자만 남기고 자동으로 하이픈(-) 추가 (숫자 최대 11자리)
      · 숫자 3자리 이하 : 010
      · 숫자 4 ~ 7자리  : 010-1234
      · 숫자 8자리 이상 : 010-1234-5678
    - 13글자(010-0000-0000)가 되면 형식 검사, 그 전에는 메세지 지우기
    - 커서가 빠져나갈 때(blur) 값이 있으면 형식 검사
      · 010-0000-0000 형식 : "올바른 휴대폰 번호!"                (success)
      · 그 외              : "010-0000-0000 형식으로 입력 필수!"  (error)

      예) 01012345678 입력 → 010-1234-5678 / 01112345678 → 형식 오류

 6. 주소검색 (id="btnSearchAddress")
    - 카카오(다음) 우편번호 API 사용 (스크립트는 join.html 에 이미 포함됨)
      참고 : https://postcode.map.daum.net/guide
    - new daum.Postcode({ oncomplete: ... }).open()
    - 주소 선택 시
        우편번호(id="postcode") ← data.zonecode
        기본주소(id="address1") ← data.address
          · 건물명(data.buildingName)이 있으면 "기본주소 (건물명)" 형태로 표시
        상세주소(id="address2") 로 커서 이동
    - daum 객체가 없으면
      "주소검색 서비스를 불러오지 못했습니다. 잠시 후 다시 시도하세요." 알림

 7. 이메일 (id="email1", id="email2", id="emailDomain", 메세지 id="checkEmailResult")

    [도메인 선택]
    - 선택값을 email2 에 표시
    - "직접입력" 이외 선택 : email2 읽기전용 (회색 배경은 CSS 에서 자동 적용됨)
    - "직접입력" 선택      : 읽기전용 해제 + email2 로 커서 이동

    [중복확인]
    - email1 keyup, email2 keyup, 도메인 선택(change) 시 검사
    - 이메일 = email1 + "@" + email2 (각각 앞뒤 공백 제거)
    - 아래 순서로 처리
      ① 이메일이 이전에 검사한 값과 같으면 아무것도 안 함
      ② 바뀌었으면 이전 중복확인 결과(checkedEmail)와 예약된 요청 취소
      ③ email1, email2 중 하나라도 비어 있으면 메세지 지우기
      ④ 형식 검사 (틀리면 서버에 요청하지 않음)
           · email1 이 영문, 숫자, . _ - 외의 문자 포함
               → "이메일 아이디 형식이 올바르지 않음!"   (error)
           · email2 가 "도메인.영문2글자이상" 형식이 아님 (예: naver.com)
               → "이메일 도메인 형식이 올바르지 않음!"  (error)
           · 통과 → "이메일 확인 중..."                (warning)
      ⑤ 타이핑이 멈추고 0.3초 뒤에 중복확인 요청 (setTimeout / clearTimeout = 디바운스)
    - 요청 함수는 requestEmailCheck(email) 로 만들고,
      { duplicate: true / false } 를 돌려주는 Promise 를 반환할 것
        → fetch("data.js") 로 회원 목록을 받아 response.json() 으로 변환
        → 회원의 email 과 같은지 검사 (대소문자 구분 없이)
        → 응답 실패(response.ok 가 false) 시 에러로 처리
      · fetch 는 .then() / .catch() 또는 async / await 중 편한 방식으로 작성
    - 응답 처리
      · 응답을 기다리는 사이에 이메일이 또 바뀌었으면 그 응답은 무시
      · 중복됨   : "이미 사용 중인 이메일!" (error)
      · 사용 가능: "사용 가능한 이메일!"    (success) → checkedEmail 에 저장
      · 요청 실패: "이메일 확인에 실패했습니다. 잠시 후 다시 시도하세요." (error)

      예) hong@gmail.com, HONG@GMAIL.COM → 이미 사용 중 / newbie@gmail.com → 사용 가능
          hong@gmail → 도메인 형식 오류

 8. 취미 (name="hobby", 4개)
    - 최대 2개까지만 선택 가능
    - 3개째 체크 시 "취미는 최대 2개까지 선택 가능!" 알림 후 방금 체크한 항목 해제

 9. 가입 (submit)
    - 아래 순서대로 검사하여, 처음 실패한 항목의 메세지를 alert 로 띄우고
      해당 항목으로 커서 이동 후 제출 취소 (event.preventDefault() 사용)
    - 모두 통과하면 그대로 제출

      | 순서 | 검사 내용                                | 알림 메세지                       | 커서 이동        |
      |------|------------------------------------------|-----------------------------------|------------------|
      |  1   | 이름이 비어 있음 (공백만 입력도 포함)    | 이름 입력 필수!                   | userName         |
      |  2   | 아이디 규칙 불만족                       | 아이디 확인 필수!                 | userId           |
      |  3   | 비밀번호 등급이 "불가"                   | 비밀번호 확인 필수!               | passwd           |
      |  4   | 비밀번호 확인 불일치 또는 비어 있음      | 비밀번호확인 확인 필수!           | passwd2          |
      |  5   | 주민번호 앞자리 6자리 아님 / 생년월일 오류 | 주민번호 앞자리 확인 필수!        | jumin1           |
      |  6   | 주민번호 뒷자리 7자리 아님 / 첫 숫자 오류 | 주민번호 뒷자리 확인 필수!        | jumin2           |
      |  7   | 휴대폰번호 형식 오류                     | 휴대폰번호 확인 필수!             | phone            |
      |  8   | 우편번호가 비어 있음                     | 주소검색 필수!                    | btnSearchAddress |
      |  9   | 상세주소가 비어 있음                     | 상세주소 입력 필수!               | address2         |
      | 10   | 이메일 비어 있음 / 형식 오류             | 이메일 확인 필수!                 | email1           |
      | 11   | 현재 이메일 ≠ 중복확인 통과 이메일       | 사용 가능한 이메일을 입력하세요!  | email1           |
      | 12   | 직업 미선택                              | 직업 선택 필수!                   | job              |
      | 13   | 취미를 하나도 선택하지 않음              | 취미 최소 한 개 이상 선택 필수!   | hobby1           |
      | 14   | 가입동기가 비어 있음                     | 가입동기 입력 필수!               | motivation       |

10. 초기화 (reset)
    - 모든 검증 메세지(아이디, 비밀번호, 비밀번호확인, 주민번호, 휴대폰, 이메일) 지우기
    - email2 읽기전용 해제
    - checkedEmail, 이전 이메일 값, 예약된 요청(setTimeout)도 초기화

11. 돌아가기 (id="btnBack")
    - 클릭 시 이전 페이지로 이동 (history.back())
