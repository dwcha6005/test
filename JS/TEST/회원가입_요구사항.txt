==========================================================================
 [실습 시험] 회원가입 폼 자바스크립트 구현
==========================================================================

■ 제공 파일
  - join.html : 회원가입 화면 (수정 금지)
  - data.js   : 가입된 회원 목록 (JSON 배열, 수정 금지)
                [ { "id": "admin", "name": "관리자" }, ... ]
                ※ <script> 로 불러오지 말고 fetch() 로 요청하여 JSON 으로 읽을 것
                ※ 원래는 백엔드 서버에 아이디를 보내서 중복 여부만 받아야 하지만,
                   서버가 없으므로 data.js 를 서버 응답 대신 사용함

■ 실행 환경
  - fetch() 는 HTML 파일을 더블클릭(file://)으로 열면 동작하지 않음
    → 톰캣(JSP 프로젝트), VS Code Live Server 등 웹 서버에서 실행할 것

■ 제출 파일
  - join.js   : join.html 과 같은 폴더에 작성
                (join.html 하단에서 <script src="join.js" defer> 로 불러옴)

--------------------------------------------------------------------------
 [공통 작성 규칙]  ※ 지키지 않으면 감점
--------------------------------------------------------------------------
  1) HTML 파일을 수정하지 말 것. (onclick, onsubmit 등 이벤트 속성 추가 금지)
  2) 모든 이벤트는 JS 에서 addEventListener() 로 연결할 것.
     (element.onclick = function() { } 방식 사용 금지)
  3) jQuery 및 $() 같은 jQuery 스타일 함수 사용 금지
     → 요소는 document.querySelector() / querySelectorAll() 로 가져올 것.
  4) var 사용 금지 → const / let 사용.
  5) 이벤트 핸들러는 화살표 함수로 작성할 것. 예) btn.addEventListener("click", () => { ... });
  6) 글자 색상을 element.style.color 로 직접 지정하지 말고,
     메세지 영역(class="msg")에 아래 CSS 클래스를 추가하는 방식으로 표시할 것.
       - success : 초록색
       - warning : 주황색
       - error   : 빨간색
     예) <div class="msg success">사용 가능한 아이디!</div>
  7) 입력값을 검사하는 로직은 "값을 받아서 결과를 반환하는 함수"로 분리할 것.
     (검사 함수 안에서 document.querySelector 등 DOM 을 사용하지 말 것)
     예) validateIdLength(id) → { valid: true, type: "success", message: "..." }
  8) 아이디/비밀번호 검증 결과를 전역 true/false 변수에 저장하지 말고,
     가입 버튼 클릭 시 현재 입력값으로 다시 검사할 것.
     (단, 아이디 중복확인은 서버 데이터가 필요하므로
      "중복확인을 통과한 아이디" 하나만 변수(checkedId)에 저장하는 것을 허용)

--------------------------------------------------------------------------
 [기능 요구사항]
--------------------------------------------------------------------------

 1. 아이디 중복확인 (id="userId", 메세지 id="checkIdResult")
    - 아이디 입력란에서 키를 눌렀다 뗄 때마다(keyup) 검사 (중복확인 버튼 없음)
    - 아이디 앞뒤 공백은 제거하고 검사
    - 아래 순서로 처리

      ① 방향키, Shift 처럼 입력값이 바뀌지 않는 키는 무시 (이전 값과 같으면 아무것도 안 함)
      ② 입력값이 바뀌었으면 이전 중복확인 결과를 취소 (checkedId 초기화)
      ③ 입력값이 비어 있으면 메세지 지우기
      ④ 길이가 4 ~ 8글자가 아니면 서버에 요청하지 않고
           "4 ~ 8글자 사이 입력 필수!" (error)
      ⑤ 길이가 맞으면 "아이디 확인 중..." (warning) 표시 후 중복확인 요청

    - 중복확인 요청
      · 키를 누를 때마다 바로 요청하지 말고, 타이핑이 멈추고 0.3초 뒤에 요청할 것
        (setTimeout / clearTimeout 사용 → 이런 방식을 "디바운스"라고 함)
        예) "newuser" 를 빠르게 입력 → 요청은 1번만 감
      · 요청 함수는 requestIdCheck(id) 로 만들고,
        { duplicate: true / false } 를 돌려주는 Promise 를 반환할 것
        → fetch("data.js") 로 회원 목록을 받아 response.json() 으로 변환
        → 같은 아이디가 있는지 검사 (대소문자 구분 없이, for...of 또는 some() 사용)
        → 응답 실패(response.ok 가 false) 시 에러로 처리
        ※ 나중에 백엔드가 생기면 이 함수만 바꾸면 되도록 만드는 것이 목적
           예) fetch(`/member/checkId?id=${아이디}`) → 서버 응답 { "duplicate": true }
      · fetch 는 .then() / .catch() 또는 async / await 중 편한 방식으로 작성

    - 응답 처리
      · 응답을 기다리는 사이에 아이디가 또 바뀌었으면 그 응답은 무시할 것
      · 중복됨   : "이미 사용 중인 아이디!"  (error)
      · 사용 가능: "사용 가능한 아이디!"     (success) → checkedId 에 저장
      · 요청 실패: "아이디 확인에 실패했습니다. 잠시 후 다시 시도하세요." (error)

      예) admin, ADMIN, hong → 이미 사용 중 / abc → 길이 부족 / newuser → 사용 가능

 2. 비밀번호 강도 (id="passwd", 메세지 id="checkPasswdResult")
    - 입력할 때마다(input) 검사
    - 허용 문자 : 영문 소문자, 영문 대문자, 숫자, 특수문자(!@#$%^&*)
    - 아래 순서대로 판정

      ① 길이가 8글자 미만 또는 16글자 초과
         → "불가 - 8 ~ 16글자 사이 입력 필수!"                         (error)
      ② 허용 문자 외의 문자(공백, 한글, 그 밖의 특수문자 등) 포함
         → "불가 - 영문, 숫자, 특수문자(!@#$%^&*)만 사용 가능!"        (error)
      ③ 4종류(소문자 / 대문자 / 숫자 / 특수문자) 중 사용한 종류의 개수

         | 조합 개수 | 등급 | CSS 클래스 | 가입 가능 |
         |-----------|------|------------|-----------|
         |    4개    | 안전 | success    |    O      |
         |    3개    | 보통 | warning    |    O      |
         |    2개    | 위험 | error      |    O      |
         |  1개 이하 | 불가 | error      |    X      |

         메세지 형식 : "안전 - 4가지 조합 사용"
                       "보통 - 3가지 조합 사용"
                       "위험 - 2가지 조합 사용"
         1개 이하    : "불가 - 영문 대/소문자, 숫자, 특수문자 중 2가지 이상 조합 필수!"

      예) abcdefgh     → 불가 (1가지)
          abcd1234     → 위험 (2가지)
          Abcd1234     → 보통 (3가지)
          Abcd123!     → 안전 (4가지)
          Abcd 123!    → 불가 (공백 포함)
          Ab1!         → 불가 (길이 부족)

 3. 비밀번호 확인 (id="passwd2", 메세지 id="checkPasswd2Result")
    - 입력할 때마다(input), 그리고 커서가 빠져나갈 때(blur) 검사
    - 비어 있음 : "비밀번호 확인 입력 필수!" (error)  ※ input 이벤트에서는 메세지만 지움
    - 일치      : "비밀번호 확인 완료!"      (success)
    - 불일치    : "비밀번호 다름!"           (error)
    - 비밀번호(passwd) 입력란을 수정해도, 비밀번호 확인란에 값이 있으면
      일치 여부를 다시 검사하여 표시할 것

 4. 주민번호 (id="jumin1", id="jumin2")
    - 숫자 외의 문자를 입력하면 즉시 제거 (숫자만 남김)
    - 앞자리 6자리 입력 완료 시 뒷자리 입력란으로 커서 이동
    - 뒷자리 7자리 입력 완료 시 뒷자리 입력란에서 커서 제거

 5. 주소검색 (id="btnSearchAddress")
    - 카카오(다음) 우편번호 API 사용 (스크립트는 join.html 에 이미 포함됨)
      참고 : https://postcode.map.daum.net/guide
    - new daum.Postcode({ oncomplete: ... }).open()
    - 주소 선택 시
        우편번호(id="postcode") ← data.zonecode
        기본주소(id="address1") ← data.address
          · 건물명(data.buildingName)이 있으면 "기본주소 (건물명)" 형태로 표시
            예) 부산광역시 부산진구 동천로 109 (삼한골든게이트)
        상세주소(id="address2") 로 커서 이동
    - daum 객체가 없으면(스크립트 로딩 실패)
      "주소검색 서비스를 불러오지 못했습니다. 잠시 후 다시 시도하세요." 알림

 6. 이메일 도메인 선택 (id="emailDomain")
    - 선택값을 @ 뒤 입력란(id="email2")에 표시
    - "직접입력" 이외 선택 : email2 를 읽기전용으로 설정
                             (회색 배경은 CSS 에서 자동 적용됨)
    - "직접입력" 선택      : 읽기전용 해제 + email2 로 커서 이동

 7. 취미 전체선택 (id="checkAll")
    - 전체선택 체크/해제 시 취미 3개 모두 체크/해제
    - 취미를 하나씩 체크하다가 3개가 모두 체크되면 전체선택도 자동 체크,
      하나라도 해제되면 전체선택도 자동 해제

 8. 가입 (submit)
    - 아래 순서대로 검사하여, 처음 실패한 항목의 메세지를 alert 로 띄우고
      해당 항목으로 커서 이동 후 제출 취소 (event.preventDefault() 사용)
    - 모두 통과하면 그대로 제출

      | 순서 | 검사 내용                              | 알림 메세지                       | 커서 이동        |
      |------|----------------------------------------|-----------------------------------|------------------|
      |  1   | 이름이 비어 있음 (공백만 입력도 포함)  | 이름 입력 필수!                   | userName         |
      |  2   | 아이디 길이 규칙 불만족                | 아이디 확인 필수!                 | userId           |
      |  3   | 현재 아이디 ≠ 중복확인 통과 아이디     | 사용 가능한 아이디를 입력하세요!  | userId           |
      |  4   | 비밀번호 등급이 "불가"                 | 비밀번호 확인 필수!               | passwd           |
      |  5   | 비밀번호 확인 불일치 또는 비어 있음    | 비밀번호확인 확인 필수!           | passwd2          |
      |  6   | 주민번호 앞자리가 숫자 6자리가 아님    | 주민번호 앞자리 6자리 입력 필수!  | jumin1           |
      |  7   | 주민번호 뒷자리가 숫자 7자리가 아님    | 주민번호 뒷자리 7자리 입력 필수!  | jumin2           |
      |  8   | 우편번호가 비어 있음                   | 주소검색 필수!                    | btnSearchAddress |
      |  9   | 상세주소가 비어 있음                   | 상세주소 입력 필수!               | address2         |
      | 10   | 이메일 아이디가 비어 있음              | 이메일 입력 필수!                 | email1           |
      | 11   | 이메일 도메인이 비어 있음              | 이메일 도메인 입력 필수!          | email2           |
      | 12   | 직업 미선택                            | 직업 선택 필수!                   | job              |
      | 13   | 취미를 하나도 선택하지 않음            | 취미 최소 한 개 이상 선택 필수!   | hobby1           |
      | 14   | 가입동기가 비어 있음                   | 가입동기 입력 필수!               | motivation       |

 9. 초기화 (reset)
    - 폼 초기화 시 아이디/비밀번호/비밀번호확인 메세지도 모두 지울 것
    - 이메일 도메인 입력란(email2)의 읽기전용도 해제할 것
    - 중복확인 통과 아이디(checkedId), 이전 입력값, 예약된 요청(setTimeout)도 초기화할 것

 10. 돌아가기 (id="btnBack")
    - 클릭 시 이전 페이지로 이동 (history.back())

 [가산점]
--------------------------------------------------------------------------
  - 길이 규칙(4, 8, 16 등)을 코드 곳곳에 숫자로 쓰지 않고 상수로 한 곳에 모아 관리
  - 메세지 출력 코드를 showMessage(element, result) 같은 함수 하나로 공통화
  - 폼 입력값을 getFormValues() 같은 함수로 하나의 객체에 모아서 검증 함수에 전달
  - 문자열을 이어 붙일 때 템플릿 리터럴(`${변수}`) 활용
