1. Node.js 설치
---------------------------------------------------------------------
Node.js : 브라우저 밖에서 JavaScript를 실행하게 해 주는 프로그램
npm     : Node.js와 함께 설치되는 "패키지 설치 도구" (React, Vite 등을 받아 온다)

① https://nodejs.org 접속
② "LTS" 버전을 다운로드한다. (LTS = 오래 지원하는 안정 버전)
   - Windows는 .msi 파일
③ 다운로드한 파일 실행 → Next만 계속 눌러서 설치
   - "Add to PATH" 항목은 반드시 체크된 상태로 둔다. (기본값)
   - "Tools for Native Modules" 체크 화면이 나오면 체크하지 않아도 된다.
④ 설치가 끝나면 열려 있던 VS Code, 터미널을 "모두" 닫는다.
   (설치 전에 켜 둔 프로그램은 node가 어디 있는지 모른다)

---------------------------------------------------------------------
① VS Code 실행
② 확장(Extensions, 왼쪽 네모 4개 아이콘)에서 아래를 설치하면 편하다. (선택)

3. 설치 확인
---------------------------------------------------------------------
VS Code 터미널에 입력한다.

    node -v
    npm -v

숫자(버전)가 두 줄 다 나오면 성공이다.  예) v24.11.0 / 11.6.2
→ npm -v 에서 빨간 에러가 나오면 4번으로 간다.

< 오류 >  'npm' 용어가 cmdlet, 함수, 스크립트 파일 ... 인식되지 않습니다
  원인 : Node 설치 전에 켜 둔 VS Code라서 node 위치를 모른다.
  해결 : ① VS Code 창을 "모두" 닫고 다시 실행
         ② 그래도 안 되면 PC 재부팅
         ③ 그래도 안 되면 Node 설치 파일을 다시 실행 → Repair

4. [Windows] PowerShell 스크립트 실행 허용 (처음 한 번)
---------------------------------------------------------------------
< 이런 에러가 나오면 이 단계를 한다 >

    npm : 이 시스템에서 스크립트를 실행할 수 없으므로 C:\Program Files\nodejs\npm.ps1 파일을
    로드할 수 없습니다. ...
        + CategoryInfo          : 보안 오류: (:) [], PSSecurityException
        + FullyQualifiedErrorId : UnauthorizedAccess

    - npm -v, npm install, npm run dev 등 "npm으로 시작하는 명령"을 처음 칠 때 나온다.
    - node -v 는 되는데 npm만 안 된다면 거의 이 경우다.
    - Mac, 또는 터미널이 Command Prompt(cmd)인 경우에는 나오지 않는다. → 이 단계 건너뛰기

< 왜 생기나? >
    - VS Code의 Windows 기본 터미널은 PowerShell이다.
    - npm은 PowerShell에서 npm.ps1 이라는 "스크립트 파일"로 실행된다.
    - Windows는 처음에 보안 때문에 PowerShell 스크립트 실행을 전부 막아 둔다. (Restricted)
    → Node 설치가 잘못된 것이 아니다. Windows 설정 문제다.

< 해결 >  VS Code 터미널에 아래 한 줄 입력 → 물어보면 Y 입력 후 Enter

    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

    뜻
    - Set-ExecutionPolicy : PowerShell 스크립트 실행 규칙을 바꾼다.
    - -Scope CurrentUser  : 지금 로그인한 사용자에게만 적용 (관리자 권한 필요 없음, 다른 계정에는 영향 없음)
    - RemoteSigned        : 내 PC에 있는 스크립트는 실행 허용,
                            인터넷에서 받은 서명 없는 스크립트는 계속 차단 (개발할 때 일반적으로 쓰는 설정)

    확인 : npm -v 를 다시 입력 → 숫자가 나오면 성공
    ※ 이 PC, 이 계정에서는 한 번만 하면 된다. 다음부터는 안 해도 된다.

< 설정을 바꾸고 싶지 않다면 >
    터미널 오른쪽 위 + 버튼 옆의 ∨ → Command Prompt 선택
    → 그 터미널에서 npm 명령을 쓰면 이 에러가 나지 않는다.

5. Vite란? create-react-app(CRA)과 무엇이 다른가
---------------------------------------------------------------------
React 코드(JSX, import ...)는 브라우저가 그대로 읽지 못한다.
그래서 "개발할 때 바로 보여 주고(개발 서버), 배포할 때 하나로 묶어 주는(빌드)" 도구가 필요하다.

    예전 : create-react-app (CRA) - React 팀이 만든 도구, 내부에서 webpack 사용
    지금 : Vite (비트, 프랑스어로 "빠르다")

< CRA를 쓰지 않는 이유 >
    - 2025년 2월 React 팀이 CRA를 "더 이상 새 프로젝트에 쓰지 말라(deprecated)"고 공식 발표했다.
    - 오랫동안 업데이트가 멈춰서 최신 React(19)와 패키지 충돌이 자주 난다.
    - React 공식 문서도 Vite 또는 Next.js 같은 프레임워크로 시작하라고 안내한다.

< Vite가 좋아진 점 >

    1) 개발 서버가 훨씬 빨리 켜진다
       CRA  : npm start → 프로젝트 전체 파일을 먼저 하나로 묶은(번들) 뒤에 화면을 보여 준다.
              파일이 많아질수록 켜는 데 수십 초 ~ 몇 분까지 걸린다.
       Vite : npm run dev → 묶지 않고 바로 켠다. 브라우저가 지금 필요한 파일만 그때그때 요청하면
              그 파일만 변환해서 보낸다. (브라우저의 ES 모듈 기능 사용 - 15_module_vite에서 배운 import)
              → 프로젝트가 커져도 거의 1초 안에 켜진다.

    2) 코드를 고치면 화면에 바로 반영된다 (HMR, Hot Module Replacement)
       CRA  : 파일 하나를 고쳐도 다시 묶는 과정이 있어 앱이 커지면 반영이 느려진다.
       Vite : 고친 파일 하나만 바꿔 끼운다. state도 대부분 유지된 채 화면만 바뀐다.

    3) 설치가 가볍다
       CRA  : 설치되는 패키지가 매우 많아 npm install이 오래 걸리고 node_modules가 크다.
       Vite : 필요한 것만 설치해서 훨씬 빠르고 가볍다.

    4) 설정이 단순하다
       CRA  : 설정 파일이 숨겨져 있어서 바꾸려면 eject(되돌릴 수 없음) 같은 복잡한 과정이 필요했다.
       Vite : vite.config.js 파일 하나에서 필요한 것만 추가하면 된다.

    5) React 전용이 아니다
       Vue, Svelte, 바닐라 JS 프로젝트에도 똑같이 쓴다. (15_module_vite에서 이미 사용해 봤다)

< 인터넷 예전 자료(CRA 기준)와 다른 점 - 꼭 알아 두기 >

    | 항목              | CRA (예전)                  | Vite (지금)                       |
    | 프로젝트 만들기   | npx create-react-app 이름   | npm create vite@latest 이름       |
    | 실행 명령         | npm start                   | npm run dev                       |
    | 기본 주소         | localhost:3000              | localhost:5173                    |
    | 시작 파일         | src/index.js                | src/main.jsx                      |
    | index.html 위치   | public/index.html           | 프로젝트 맨 위 index.html          |
    | JSX 파일 확장자   | .js 도 됨                   | .jsx 로 써야 함                    |
    | 환경 변수 이름    | REACT_APP_로 시작           | VITE_로 시작                       |
    |                   | process.env.REACT_APP_KEY   | import.meta.env.VITE_KEY          |
    | 배포 결과 폴더    | build                       | dist                              |

    → 인터넷 예전 강의를 볼 때 위 표처럼 바꿔서 읽으면 된다. React 코드 자체(컴포넌트, Hook)는 똑같다.

6. React 프로젝트 만들기 (Vite)
---------------------------------------------------------------------
※ Vite는 따로 설치하지 않는다. 아래 명령이 그때그때 받아서 실행한다.
★ 프로젝트는 "한 번만" 만든다. 챕터(ch01, ch02 ...)는 프로젝트 안의 폴더로 만든다.

① 프로젝트를 만들 폴더(예: C:\본인경로\React)를 VS Code로 열고 터미널에서 입력

    npm create vite@latest react-lessons

   - latest 철자 주의 (lastest X)
   - "Ok to proceed? (y)" 가 나오면 y

② 질문에 답한다. (화살표 키로 이동, Enter로 선택)
   - Select a framework  → React
   - Select a variant    → JavaScript      ← TypeScript 아님!
   - 그 밖의 질문은 기본값(Enter)

③ 설치하고 실행

    cd react-lessons
    npm install
    npm run dev

   - npm install : package.json에 적힌 React, Vite 등을 node_modules 폴더에 설치 (처음 한 번)
   - npm run dev : 개발 서버 실행 → 터미널에 나온 http://localhost:5173 을 Ctrl + 클릭
   - 끄기 : 터미널에서 Ctrl + C

④ 브라우저에 Vite + React 로고 화면이 나오면 성공!

⑤ VS Code에서 "파일 → 폴더 열기 → react-lessons" 로 프로젝트 폴더를 다시 연다.
   (앞으로는 이 폴더를 열고 수업한다)

7. 챕터 폴더 만들고 실행하기
---------------------------------------------------------------------
폴더 구조

    react-lessons/
    ├── node_modules/      ← 설치된 패키지 (건드리지 않는다, 지워도 npm install로 복구)
    ├── index.html
    ├── package.json       ← 프로젝트 정보, 설치한 패키지 목록
    ├── vite.config.js
    └── src/
        ├── main.jsx       ← 시작 파일 (여기서 챕터를 바꾼다)
        ├── index.css
        ├── ch01_jsx/
        │   └── App.jsx
        └── ch02_props/
            └── App.jsx

① 템플릿이 만든 파일 정리 (지워도 된다)
   src/App.jsx, src/App.css, src/assets 폴더

② src 안에 ch01_jsx 폴더를 만들고 App.jsx 작성

    export default function App() {
      return <h1>Hello React</h1>;
    }

③ src/main.jsx 를 아래처럼 바꾼다.

    import { StrictMode } from "react";
    import { createRoot } from "react-dom/client";
    import "./index.css";

    import App from "./ch01_jsx/App.jsx";
    // import App from "./ch02_props/App.jsx";

    createRoot(document.getElementById("root")).render(
      <StrictMode>
        <App />
      </StrictMode>
    );

④ 챕터를 바꿀 때는 main.jsx의 import 줄만 바꾼다. (한 줄만 주석 해제)
   저장하면 브라우저가 자동으로 바뀐다.

주의
- JSX가 들어간 파일은 확장자를 .jsx 로 한다. (.js로 하면 Vite에서 에러)
- 컴포넌트 이름은 대문자로 시작한다. (App, Header ...)
- 다음 날 수업 시작할 때는 react-lessons 폴더를 열고 npm run dev 만 하면 된다.
  (npm install은 다시 할 필요 없다)

9. 자주 묻는 질문
---------------------------------------------------------------------
Q. 화면이 하얗기만 해요.
A. F12 → Console 탭의 빨간 에러를 읽어 본다. 대부분 import 경로 오타, 대소문자, .jsx 확장자 문제다.

Q. 'vite'은(는) 내부 또는 외부 명령 ... 이 아닙니다.
A. npm install을 안 했다. react-lessons 폴더에서 npm install 후 npm run dev

Q. npm run dev 했는데 "Missing script: dev" 라고 나와요.
A. 터미널 위치가 react-lessons가 아니다. 터미널 앞부분 경로를 확인하고 cd react-lessons

Q. Port 5173 is in use 라고 나와요.
A. 다른 터미널에서 이미 켜져 있다. 그 터미널에서 Ctrl + C, 또는 Vite가 알려 주는 다른 주소(5174)로 접속

Q. 인터넷 강의는 npm start 라고 하던데요?
A. CRA 기준 예전 자료다. 5번의 표를 참고해서 npm run dev 로 바꿔 읽는다.

Q. 다른 컴퓨터로 프로젝트를 옮기고 싶어요.
A. node_modules 폴더는 빼고 복사한다. (용량이 크다) 옮긴 곳에서 npm install 하면 다시 생긴다.
   Git에 올릴 때도 .gitignore에 node_modules가 들어 있어서 자동으로 빠진다.
