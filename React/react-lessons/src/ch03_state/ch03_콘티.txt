1교시 (50분) - 이벤트, State 개념
---------------------------------------------------------------------
[순서01] 이벤트 연결 (15분)
  - 시연 : A버튼 / B버튼 → 하나의 함수로 처리 (e.target.name)
           주석 처리된 L 버튼을 풀면 → 페이지가 열리자마자 alert → 원복
  - 포인트 : onClick={함수} 는 전달, onClick={함수()} 는 즉시 실행. 인자는 () => 함수(값)
  - 10_event 01 "자주 하는 실수 - 함수 뒤에 괄호"와 같은 내용임을 연결한다.

[순서02] 일반 변수 (10분)  ★ State가 필요한 이유를 체감
  - 시연 : + 를 여러 번 → 콘솔은 1, 2, 3 증가하지만 화면은 계속 0

[순서03] useState (25분)
  - 판서 : const [값, 값을바꾸는함수] = useState(초기값)
  - 시연 : + 클릭 → 화면 변경 + 콘솔 "Step03 렌더링" 로그 (2번씩 찍히는 이유는 [순서07])
           전등 스위치 → boolean state 토글 setIsOn(!isOn)
  - 포인트 : setter로 바꾸면 "컴포넌트 함수 전체가 다시 실행"된다.
            훅은 컴포넌트 맨 위에서만 호출

2교시 (50분) - 입력과 폼 + 실습
---------------------------------------------------------------------
[순서04] 제어 컴포넌트 (10분)
  - 시연 : onChange를 지우면 입력이 안 됨 → value를 state가 고정하고 있기 때문
  - 포인트 : 입력값이 항상 state에 있다 → 미리보기, 글자 수 바로 가능 (11_form과 비교)

[순서05] 객체 state (10분)  ★ 기존 자료의 핵심 설명 유지
  - 시연 : 아래 pre에 JSON이 실시간으로 바뀌는 것 확인
  - 시연 : handleChange를 "직접 수정 후 setForm(form)" 으로 바꾸면 화면이 안 바뀜 → 원복
  - 포인트 : 참조 타입은 새 객체를 만들어야 바뀐 것으로 인식. {...form, [name]: value}

[순서06] 폼 제출 (5분)
  - 시연 : 3자 입력 후 Enter → 메시지 / 4자 이상 → 환영 + 입력창 비워짐

[순서07] StrictMode (설명만)
  - 포인트 : 로그가 두 번 → 개발 모드의 정상 동작. 기존 자료처럼 StrictMode를 지우지 않는다.

예상 질문 / 자주 막히는 곳
---------------------------------------------------------------------
- "setCount 다음 줄에서 console.log(count) 했는데 이전 값이 나와요"
  → setCount는 "다음 렌더링"의 값을 예약할 뿐, 지금 실행 중인 함수의 count는 그대로다. (ch04 [순서07] 함수형 업데이트)
- select에 key를 쓰는 실수 (기존 자료) → option에는 value를 쓴다. key는 목록 렌더링용 (ch04)
- [name]: 대괄호를 빼먹으면 "name"이라는 key가 새로 생긴다.
