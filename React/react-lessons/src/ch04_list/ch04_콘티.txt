1교시 (50분) - map, key, filter
---------------------------------------------------------------------
[순서01] map (10분)
  - 시연 : key={fruit}를 지우면 콘솔에 key 경고 → 원복
  - 포인트 : { } 안에 for문 불가 → map이 JSX 배열을 만든다.

[순서02] key가 필요한 이유 (15분)  ★ 반드시 직접 체험
  - 시연 : 양쪽 목록의 "첫 번째" 입력창에 각각 "A"를 입력 → [맨 앞에 추가]
           왼쪽(index key) : A가 "새 항목 3" 옆으로 이동해 있음 (잘못됨)
           오른쪽(id key)  : A가 "첫 번째" 옆에 그대로 있음 (정상)
  - 포인트 : key = React가 항목을 구분하는 이름표. 고유한 id를 쓴다.

[순서03] filter (10분)
  - 시연 : "품절 상품 숨기기" 체크 → 키보드가 사라짐
  - 포인트 : 체크박스는 value가 아니라 checked / e.target.checked

[순서04] 배열 state 추가 (15분)
  - 시연 : handleAdd를 todos.push + setTodos(todos)로 바꾸면 → 화면이 안 바뀜 → 원복
  - 판서 : 추가 [...arr, new] / 삭제 filter / 수정 map (App.jsx 상단 표)

2교시 (50분) - 삭제, 수정, 함수형 업데이트 + 실습
---------------------------------------------------------------------
[순서05] 삭제 / [순서06] 수정 (10분)
  - 시연 : 체크박스로 완료 토글 (줄긋기), 삭제, 하단 개수 변화
  - 포인트 : map 안의 { ...todo, done: !todo.done } → ch03의 객체 복사와 같은 원리

[순서07] 함수형 업데이트 (10분)
  - 시연 : [+3 잘못된 방법] → 1 증가 / [+3 함수형 업데이트] → 3 증가
  - 포인트 : 이전 값으로 새 값을 만들 때는 prev => ... 사용

[순서08] 항목 컴포넌트 분리 (5분)
  - 포인트 : key는 map 안의 컴포넌트에. 함수(onDelete)를 props로 내려주기 → ch05 예고

예상 질문 / 자주 막히는 곳
---------------------------------------------------------------------
- map 안에서 { }를 쓰고 return을 빼먹음 → 아무것도 안 나옴
    items.map((item) => { <li>{item}</li> })   (X)
    items.map((item) => <li>{item}</li>)       (O)
- onClick={handleDelete(todo.id)} → 렌더링 중 바로 삭제 실행됨. () => handleDelete(todo.id)
- "index를 key로 쓰면 안 되나요?" → 순서가 바뀌지 않는 고정 목록이면 괜찮다.
