1교시 (50분) - 소셜 로그인 흐름 따라가기
---------------------------------------------------------------------
[순서01] 소셜 로그인 흐름 (10분)  → App.jsx 주석
  - 질문 던지기 : "카카오로 로그인하면 우리 사이트가 내 카카오 비밀번호를 알까?" → 모른다. 그럼 어떻게?
  - 판서 : 우리 앱 → 카카오(동의) → code 들고 돌아옴 → code를 토큰으로 교환 → 토큰 저장
  - "왜 바로 토큰을 안 주고 code를 주나?" → 주소창에 남는 값이라 일회용 교환권만 준다

완성본 시연 (5분)
  - 마이페이지 클릭 → 로그인 페이지로 튕김
  - 카카오 로그인 → 동의 화면 → "로그인 처리 중" → 마이페이지
  - ▶ 주소창을 크게 보여 주며 단계마다 바뀌는 주소 읽기
       /oauth/kakao?state=...  →  /oauth/callback?code=...&state=...  →  /mypage

[순서02] 가짜 인증 서버 (10분)  → fakeAuthServer.js
  - issueCode / exchangeCodeForToken / getMe 세 함수가 "남의 서버" 역할
  - 토큰 모양(헤더.내용.서명) → 마이페이지에서 내용이 그대로 읽히는 것 확인 (암호화 아님!)

[순서04] AuthContext (10분)  → context/AuthContext.jsx
  - ch10 useAuth 패턴 그대로. user / checking / startLogin / completeLogin / logout

[순서05] 로그인 페이지와 state (10분)  → pages/Login.jsx
  - state : 보냈다가 그대로 돌려받는 값 → 다르면 "남이 만든 로그인 요청" (CSRF 방지)
  - ▶ 시연 : 주소창에 /oauth/callback?code=aaa&state=bbb 직접 입력 → "state 값이 다릅니다"

2교시 (50분) - 콜백, 저장소, 보호 페이지 + 실습
---------------------------------------------------------------------
[순서06] 동의 화면 / [순서07] 콜백 (10분)  → OAuthConsent.jsx, OAuthCallback.jsx
  - 동의 → code 붙여서 콜백으로 / 취소 → error 붙여서 콜백으로
  - ▶ 시연 : [취소] → 로그인 페이지에 "로그인을 취소했습니다."
  - ★ useRef로 한 번만 요청하는 이유 : StrictMode가 useEffect를 두 번 실행 + code는 일회용
    (ref 검사 두 줄을 지우고 로그인 → "이미 사용된 인가 코드" 에러 → 원복)

[순서03] 토큰 저장소 3가지 (10분)  → tokenStorage.js  ★ 핵심 시연
  - ▶ localStorage 선택 로그인 → Application 탭에서 auth_token 확인 → 탭 닫고 다시 열어도 로그인 유지
  - ▶ sessionStorage 선택 로그인 → 새로고침은 유지, 탭을 닫았다 열면 로그아웃
  - ▶ 쿠키 선택 로그인 → Cookies에서 Expires 확인 → 2분 뒤 새로고침하면 로그아웃
  - ▶ localStorage는 2분이 지나도 값이 남아 있지만, 새로고침하면 getMe가 "만료"로 거절 → 자동 삭제
    → "저장소에 남아 있다 ≠ 로그인 상태" (서버가 확인해야 한다)

[순서08] 보호 페이지 / [순서09] 새로고침 유지 / [순서10] 로그아웃 (5분)
  - RequireAuth에서 checking을 먼저 보는 이유 : 없으면 새로고침할 때마다 로그인 페이지로 튕김
    (if (checking) 줄을 지우고 마이페이지에서 새로고침 → 튕김 → 원복)

[순서11] 실제 서비스와 다른 점 (5분)  → App.jsx 아래 표
  - 토큰 교환은 백엔드, 진짜 서명, HttpOnly 쿠키

예상 질문 / 자주 막히는 곳
---------------------------------------------------------------------
- "localStorage에 토큰 두면 위험하지 않나요?" → XSS로 읽힐 수 있다. 그래서 실무는 HttpOnly 쿠키를 많이 쓴다.
- "로그인 정보를 그냥 localStorage에 { name } 으로 저장하면 안 되나요?"
  → 누구나 개발자 도구에서 바꿀 수 있다. 서버가 발급하고 확인하는 토큰이어야 한다.
- 콜백에서 "이미 사용된 인가 코드" → 콜백 페이지를 새로고침함 (code는 일회용) → 정상 동작
- 다른 챕터에서 쓴 localStorage 값과 섞여 헷갈리면 Application 탭에서 Clear site data
