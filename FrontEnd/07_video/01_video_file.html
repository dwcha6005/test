웹 영상의 기본 개념

1. 웹에서 영상이 재생되는 원리

웹페이지에 영상을 표시하려면 HTML로 영상 파일을 연결하고, 브라우저가 해당 파일을 해석하여 재생한다.

  • HTML : 영상이 표시될 위치와 재생 방법 지정
  • 영상 파일 : 실제 영상과 음성 데이터 저장
  • 브라우저 : 영상 파일을 가져와 해독하고 화면과 소리로 출력
  • CSS : 영상의 크기, 위치, 여백 등 화면 디자인 담당

HTML은 영상 데이터를 직접 저장하는 것이 아니라, 외부 영상 파일을 연결하여 재생하는 역할을 한다.

2. 영상 파일의 구성

영상 파일에는 영상 데이터뿐 아니라 음성, 자막, 시간 정보 등 다양한 데이터가 포함될 수 있다.

영상 파일을 이해하려면 컨테이너와 코덱의 차이를 알아야 한다.

2-1. 컨테이너(Container)

영상, 음성, 자막 등의 데이터를 하나의 파일로 묶는 형식이다.

  • MP4 : 웹에서 널리 사용하는 컨테이너 형식
  • WebM : 웹 재생을 위해 널리 사용되는 미디어 컨테이너 형식
  • MOV : 영상 편집 환경에서 자주 사용하는 컨테이너 형식
  • MKV : 다양한 영상, 음성, 자막 트랙을 담을 수 있는 컨테이너 형식

2-2. 코덱(Codec)

영상과 음성 데이터를 압축하거나 압축된 데이터를 해독하는 기술이다.

  • H.264 : 웹 영상에서 널리 사용되는 영상 코덱
  • H.265(HEVC) : 높은 압축 효율을 목표로 하는 영상 코덱
  • VP9 : 웹에서 사용되는 영상 코덱
  • AV1 : 높은 압축 효율을 목표로 개발된 영상 코덱
  • AAC : 널리 사용되는 음성 코덱
  • Opus : 음성 및 오디오 스트리밍 등에 사용되는 코덱

MP4는 컨테이너이며 H.264는 영상 코덱이다. MP4 파일 안에 H.264 영상과 AAC 음성이 함께 들어갈 수 있다.

따라서 파일 확장자가 MP4라고 해서 모든 브라우저와 기기에서 반드시 재생되는 것은 아니다. 내부 코덱과 인코딩 설정도 영향을 준다.

2-3. 영상 파일의 구조 예시

sample.mp4
├── 컨테이너 : MP4
├── 영상 트랙 : H.264
├── 음성 트랙 : AAC
└── 시간 정보 및 기타 메타데이터

위 구조는 이해를 돕기 위한 예시다. 실제 파일의 구성은 인코딩 방식과 포함된 트랙에 따라 달라질 수 있다.

3. 영상의 해상도(Resolution)

해상도는 영상 화면을 구성하는 가로와 세로 픽셀의 개수다.

  • 1280 × 720 : HD, 일반적으로 720p라고 부름
  • 1920 × 1080 : Full HD, 일반적으로 1080p라고 부름
  • 2560 × 1440 : QHD
  • 3840 × 2160 : UHD, 일반적으로 4K라고 부름

일반적으로 해상도가 높으면 더 많은 세부 정보를 표현할 수 있지만, 필요한 데이터량도 증가할 수 있다.

단, 해상도만으로 화질이 결정되는 것은 아니다. 비트레이트, 코덱, 원본 품질, 인코딩 설정 등도 화질에 영향을 준다.

4. 화면 비율(Aspect Ratio)

화면 비율은 영상의 가로와 세로의 비율이다.

  • 16:9 : 일반적인 유튜브 영상, 강의 영상, 모니터 화면
  • 9:16 : 세로형 숏폼 영상
  • 4:3 : 과거 TV 및 일부 영상 콘텐츠
  • 1:1 : 정사각형 영상 콘텐츠

1920 × 1080은 16:9 비율이고, 1080 × 1920은 9:16 비율이다.

화면 비율과 실제 표시 영역의 비율이 다르면 여백이 생기거나 영상 일부가 잘릴 수 있다. CSS의 object-fit 속성으로 표시 방식을 조절할 수 있다.

5. 프레임레이트(Frame Rate)

프레임레이트는 1초 동안 표시되는 영상 프레임의 개수이며 FPS(Frame Per Second)로 나타낸다.

  • 24fps : 영화에서 널리 사용되는 프레임레이트
  • 30fps : 일반적인 온라인 영상과 강의 영상 등에 사용
  • 60fps : 움직임이 부드럽게 표현되는 영상이나 게임 영상 등에 사용

프레임레이트가 높으면 움직임을 더 촘촘하게 표현할 수 있지만, 필요한 데이터량과 처리량도 증가할 수 있다.

프레임레이트가 높다고 무조건 좋은 것은 아니다. 콘텐츠의 목적과 원본 촬영 환경에 맞는 설정을 선택해야 한다.

6. 비트레이트(Bit Rate)

비트레이트는 일정 시간 동안 처리되는 데이터량이다. 영상의 경우 보통 Mbps 단위로 표현한다.

  • 비트레이트가 높으면 같은 조건에서 화질을 유지하는 데 유리할 수 있다.
  • 비트레이트가 높을수록 파일 용량도 커지는 경향이 있다.
  • 같은 비트레이트라도 코덱과 인코딩 설정에 따라 화질이 달라질 수 있다.

영상의 대략적인 용량은 비트레이트와 재생 시간으로 추정할 수 있다.

파일 크기(bit) ≈ 전체 비트레이트(bit/s) × 재생 시간(s)

예를 들어 전체 비트레이트가 5Mbps인 영상이 10분이라면 다음과 같이 계산할 수 있다.

5,000,000 × 600 ÷ 8 = 약 375,000,000바이트

즉 약 375MB(십진 단위)이며, 실제 용량은 오디오 비트레이트, 컨테이너 오버헤드 및 인코딩 특성에 따라 달라진다.

7. 인코딩(Encoding)과 디코딩(Decoding)

7-1. 인코딩

영상이나 음성 데이터를 특정 코덱과 설정에 맞춰 압축하거나 변환하는 과정이다.

영상 편집 프로그램에서 해상도, 프레임레이트, 코덱, 비트레이트 등을 지정하고 MP4 파일로 내보내는 과정이 대표적인 예다.

7-2. 디코딩

압축된 영상이나 음성 데이터를 해독하여 재생할 수 있도록 처리하는 과정이다.

브라우저는 지원되는 코덱으로 압축된 데이터를 해독해 화면과 소리로 출력한다.

7-3. 웹 게시용 영상 설정을 선택할 때

  • 일반적인 웹 영상은 호환성이 넓은 형식과 코덱을 우선 고려한다.
  • 영상의 용도에 맞게 해상도와 비트레이트를 설정한다.
  • 모바일 사용자가 많다면 데이터 사용량과 로딩 속도를 고려한다.
  • 영상 편집용 원본과 웹 게시용 파일을 구분해 관리할 수 있다.

8. 웹 영상과 스트리밍

8-1. 일반 영상 파일 재생

HTML video 태그로 MP4 등의 영상 파일을 연결하면 브라우저가 서버에서 데이터를 받아 재생한다.

재생 전에 파일 전체를 반드시 다운로드해야 하는 것은 아니다. 서버가 부분 요청을 지원하는지, 브라우저의 로딩 방식이 어떠한지에 따라 필요한 데이터만 받아 재생할 수 있다.

8-2. 스트리밍 서비스

YouTube나 온라인 강의 서비스처럼 대규모 영상 서비스는 영상 데이터를 효율적으로 전달하기 위해 다양한 기술을 사용할 수 있다.

  • HTTP 기반 데이터 전송
  • HLS, MPEG-DASH 등의 적응형 스트리밍 기술
  • CDN을 이용한 콘텐츠 전달
  • 네트워크 상황에 따른 화질 변경

일반적인 HTML video 사용과 HLS·DASH 같은 스트리밍 기술은 구분해서 이해해야 한다. 스트리밍 서비스는 영상 재생 태그뿐 아니라 서버와 전송 기술도 함께 활용한다.

9. 웹 영상 게시 시 주의할 점

  • 영상 파일 경로가 올바른지 확인한다.
  • 브라우저와 기기에서 영상 코덱을 지원하는지 확인한다.
  • 파일 용량이 지나치게 크지 않은지 확인한다.
  • 모바일 화면에서도 영상이 잘 표시되는지 확인한다.
  • 자동 재생에만 의존하지 않고 재생 제어 기능을 고려한다.
  • 영상에 대사나 중요한 소리가 있다면 자막 제공을 고려한다.
  • 타인의 영상이나 음원을 사용할 때 저작권과 이용 조건을 확인한다.

10. 핵심 정리

  • HTML의 video 태그는 영상 파일을 웹페이지에 표시하고 재생하는 데 사용한다.
  • MP4는 컨테이너이며 H.264는 영상 코덱이다.
  • 해상도는 화면의 픽셀 수, FPS는 초당 프레임 수, 비트레이트는 초당 데이터량이다.
  • 인코딩은 데이터를 압축·변환하는 과정이며, 디코딩은 압축된 데이터를 해독하는 과정이다.
  • 웹 영상은 화질뿐 아니라 용량, 로딩 시간, 기기 호환성도 고려해야 한다.
  • 일반 영상 파일 재생과 적응형 스트리밍 서비스는 서로 다른 개념이다.
