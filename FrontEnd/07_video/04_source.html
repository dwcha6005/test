Video Source

여러 영상 파일 중 브라우저가 재생할 수 있는 파일을 선택하도록 구성하기

1. 이번 수업의 목표

  • video의 src 속성과 source 요소의 차이를 설명할 수 있다.
  • 하나의 영상에 여러 파일을 제공하는 이유를 이해할 수 있다.
  • type 속성에 MIME 타입을 지정하는 이유를 이해할 수 있다.
  • 파일 경로 오류와 브라우저의 미디어 형식 지원 문제를 구분할 수 있다.
  • 영상 재생 실패 시 개발자 도구를 이용해 원인을 확인할 수 있다.

2. video의 src 속성

가장 간단한 방법은 video 요소에 src를 지정하는 것이다.

<video src="assets/videos/flower.mp4" controls>
    브라우저가 video 요소를 지원하지 않습니다.
</video>

이 방식은 영상 파일 하나를 재생할 때 간단하다.

하지만 같은 영상을 MP4, WebM 등 여러 형식으로 준비했다면 어떻게 해야 할까?

핵심: video src는 특정 파일 하나를 지정한다. 여러 후보 파일을 제공하려면 source 요소를 사용할 수 있다.

3. source 요소 사용하기

source 요소는 미디어의 후보 파일을 지정한다. 하나의 video 안에 여러 개를 배치할 수 있다.

<video controls>
    <source src="assets/videos/flower.webm" type="video/webm">
    <source src="assets/videos/flower.mp4" type="video/mp4">
    브라우저에서 영상을 재생할 수 없습니다.
</video>

브라우저는 위에서부터 후보를 확인하고, 재생 가능한 소스를 선택한다.

  • 첫 번째 파일을 재생할 수 있으면 해당 파일을 사용한다.
  • 첫 번째 파일을 지원하지 않으면 다음 후보를 확인할 수 있다.
  • 재생할 수 있는 후보가 없다면 영상이 재생되지 않을 수 있다.
주의: 파일을 여러 개 적었다고 모든 오류가 자동으로 해결되는 것은 아니다. 경로가 잘못되었거나, 파일이 손상되었거나, 영상 코덱을 지원하지 않으면 재생에 실패할 수 있다.

4. src와 source 비교

구분 video의 src source 요소
파일 지정 주로 하나의 파일 여러 후보 파일
사용 형태 <video src="..."> <video><source ...></video>
주요 목적 간단한 단일 파일 재생 형식별 대체 파일 제공

두 방식 모두 유효하다. 무조건 source가 더 좋은 것이 아니라, 여러 형식의 대체 파일이 필요한지에 따라 선택한다.

5. type 속성

type은 해당 파일의 미디어 타입을 브라우저에 알려준다.

<source src="flower.mp4" type="video/mp4">
<source src="flower.webm" type="video/webm">

대표적인 영상 MIME 타입은 다음과 같다.

  • video/mp4 : MP4 컨테이너의 영상 파일
  • video/webm : WebM 컨테이너의 영상 파일
  • video/ogg : Ogg 컨테이너의 영상 파일

type을 지정하면 브라우저가 파일을 직접 내려받기 전에 형식 지원 여부를 판단하는 데 도움이 된다.

중요: MIME 타입만 보고 실제 코덱까지 완벽하게 판단할 수 있는 것은 아니다. 같은 MP4 파일이라도 내부 영상·음성 코덱에 따라 재생 가능 여부가 달라질 수 있다.

6. 확장자와 코덱은 다르다

영상 재생 문제를 해결하려면 파일 확장자와 코덱의 차이를 알아야 한다.

  • 확장자: 파일 이름 뒤에 붙는 .mp4, .webm 등의 표시
  • 컨테이너: 영상과 음성, 자막 등의 데이터를 담는 형식
  • 코덱: 영상이나 음성을 압축하고 해제하는 방식

예를 들어 MP4는 컨테이너 형식이다. MP4 파일이라고 해서 내부 영상이 반드시 같은 코덱으로 인코딩되어 있는 것은 아니다.

따라서 다음 상황이 가능하다.

  • 확장자는 MP4인데 특정 브라우저에서 재생되지 않는다.
  • 영상은 나오지만 음성이 나오지 않는다.
  • 한 브라우저에서는 재생되지만 다른 브라우저에서는 재생되지 않는다.
파일 확장자만 바꾼다고 영상 형식이 변환되는 것은 아니다. 코덱이나 컨테이너를 바꾸려면 적절한 변환 프로그램으로 인코딩해야 할 수 있다.

7. 프로젝트 파일 구성하기

HTML 파일과 영상 파일을 다음처럼 배치한다고 가정한다.

video-study/
├── 04_video_source.html
└── assets/
    └── videos/
        ├── flower.mp4
        └── flower.webm

HTML 파일에서 영상 파일까지의 상대 경로는 다음과 같다.

assets/videos/flower.mp4
assets/videos/flower.webm

경로는 HTML 파일의 위치를 기준으로 해석된다. 파일을 다른 폴더로 옮기면 상대 경로도 다시 확인해야 한다.

실습 전 확인: 예시 파일 이름만 적어 두어서는 영상이 재생되지 않는다. 실제 영상 파일을 해당 폴더에 준비해야 한다. 두 파일은 동일한 영상의 서로 다른 형식이어야 한다.

9. JavaScript로 오류 확인하기

영상이 재생되지 않을 때는 video 요소의 상태와 오류 정보를 확인할 수 있다.

const video = document.querySelector("video");

console.log(video.currentSrc);
console.log(video.readyState);
console.log(video.networkState);
console.log(video.error);
  • currentSrc : 브라우저가 선택한 미디어 URL
  • readyState : 미디어 데이터를 어느 정도 확보했는지 나타내는 값
  • networkState : 미디어 리소스 로딩 상태
  • error : 미디어 오류 정보. 오류가 없으면 null일 수 있다.

오류 이벤트를 등록하면 재생 실패가 발생했을 때 확인할 수 있다.

video.addEventListener("error", function () {
    console.log("영상 로딩 또는 재생 중 오류가 발생했습니다.");
    console.log(video.error);
});

오류 객체가 제공하는 정보만으로 모든 원인을 확정할 수는 없다. 브라우저 개발자 도구의 Network 탭과 Console도 함께 확인한다.

10. 재생 실패 원인 구분하기

증상 확인할 내용
파일을 찾을 수 없음 경로, 파일명, 대소문자, Network 응답 상태
파일은 있지만 재생 불가 파일 손상, 컨테이너 및 코덱 지원 여부
영상은 나오지만 소리가 없음 음성 트랙, 음성 코덱, 음소거 상태
로컬에서는 되지만 서버에서는 실패 서버 응답, MIME 타입, 접근 권한, 네트워크 설정
특정 브라우저에서만 실패 브라우저별 컨테이너·코덱 지원 차이

실무에서는 무작정 속성을 바꾸기보다 파일 경로 → 네트워크 응답 → 형식과 코덱 순서로 확인하면 원인을 좁히기 쉽다.
